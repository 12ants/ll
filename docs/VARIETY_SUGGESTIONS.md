# Terrene World Studio — Rendering Detail & Variety Suggestions

## Current state

The renderer currently produces four detail classes:
- **Trees** — icosahedron canopy + cylinder trunk, seeded scale/rotation, HSL green variation
- **Benches** — box seat + cylinder legs + box bin, placed every 31st tree point
- **Building facades** — box window panes in 5 preset tone trios, rooftop box/cylinder equipment
- **Bridges** — box deck + railing + cylinder piers, fixed gray-brown palette

Variety is generated by a single `tone` float (0–1) per feature, mapped to narrow HSL or palette-index ranges. Geometry is limited to three primitives. The following suggestions expand detail and variety while respecting the existing performance budgets.

---

## 1. Expand tree species diversity

**Current:** One canopy shape (icosahedron, detail 1), one trunk geometry, one narrow green hue band (`0.22 + tone * 0.045`).

**Suggestions:**
- Add a `species` field to `Detail` derived from a second hash of the feature geometry. Map 4–6 species to distinct canopy shapes and trunk proportions:
  - **Spherical** — `icosahedronGeometry(1, 2)` (smooth ball)
  - **Conical** — `coneGeometry(1, 1, 8)` (pine/fir)
  - **Oval** — `sphereGeometry(1, 8, 6)` scaled `(1, 1.4, 1)` (deciduous)
  - **Flat-top** — `cylinderGeometry(1, 1.2, 0.5, 8)` + `sphereGeometry(0.7, 8, 6)` on top (acacia-style)
- Map species to hue families so the canopy band reads as multiple tree types rather than one green fog:
  - Conifers: `hsl(0.28–0.34, ...)` (yellow-green to deep green)
  - Deciduous: `hsl(0.22–0.28, ...)` (green)
  - Autumn palette (when `hour` is in 16–19 range): shift saturation down and lightness up for warm tones
- Vary trunk radius per species (pines get thinner trunks, oaks get thicker).

**Budget impact:** Negligible — same instance count, different geometry args and color mapping.

---

## 2. Add ground cover / undergrowth

**Current:** Trees float at `y = 0` (or terrain elevation) with no understory.

**Suggestions:**
- Collect small circular polygons from the `landcover` layer (`class === "grass"` with area < 500 m²) and `park` interiors.
- Scatter low, flat instanced meshes (box, scale `(0.4, 0.06, 0.4)`) as ground cover, colored in `p.park` hue with lightness variation.
- In parks, add larger shrub meshes (`icosahedronGeometry(1, 0)` scaled `(0.6, 0.25, 0.6)`) at lower density than trees.
- Cap at `QUALITY.trees * 0.3` instances so Eco tier stays fast.

**Data source:** Same `queryRenderedFeatures` pass already runs for trees; no extra tile queries needed.

---

## 3. Vary bench geometry by context

**Current:** Every bench is identical: box seat + cylinder legs + box bin.

**Suggestions:**
- Hash the park/landcover feature to choose 2–3 bench variants:
  - **Park bench** — current design, wood tone
  - **Modern bench** — single box slab, no legs, metal gray
  - **Picnic table** — wider box (`scale(2.5, 0.12, 0.8)`) + 4 thin cylinder legs
- Add a `kind` field to `Detail` and branch in `Instances` to swap geometry args.
- Place picnic tables only in larger parks (area threshold) so they don't clutter every verge.

---

## 4. Add street furniture beyond benches

**Current:** Only benches appear as amenities.

**Suggestions:**
- Query `highway` features (`class` in `["footway", "path", "pedestrian"]`) for placement points.
- Add new detail types with low budgets:
  - **Lampposts** — thin cylinder (`radius 0.08, height 3–5m`) + small sphere top. Placed every ~20m along paths. Capped at 200.
  - **Bollards** — cylinder (`radius 0.12, height 0.6`), placed at path/road intersections. Capped at 150.
  - **Bus stops** — box shelter (`scale(2, 1.8, 1)`), placed on major road centerlines where a `bus_stop` node exists in the vector tile properties. Capped at 30.
- Each type gets its own `kind` and color rule (lampposts: dark gray; bollards: warm gray; bus stops: transparent blue glass or project palette mid-tone).

**Data source:** Already queried in `details-data.ts` via the `roads` layer; `highway` class is present in transportation tiles.

---

## 5. Building facade variety

**Current:** 5 preset `[pane, ground, lit]` trios. All windows are identical boxes. Rooftop equipment is 3 shapes in 2 colors.

**Suggestions:**
- Expand `FACADE_TONES` to 10–12 trios so adjacent buildings rarely match. The hash already selects by `tone * length % length`, so this is a pure data change.
- Add window shape variety:
  - **Rectangular** — current box
  - **Arched** — box with a half-cylinder cap (merge geometry or use a second instanced mesh with `sphereGeometry(0.5, 8, 4, 0, Math.PI * 2, 0, Math.PI / 2)` positioned above the box)
  - **Sliding door (ground floor)** — wider, shorter box, only when `ground_floor` is true
- Add balcony rails: thin box strips protruding from the facade at every 3rd floor on buildings with `ground_floor && height > 15`.
- Rooftop variety: add a small cone (`coneGeometry`) for water towers and a flat box for HVAC units.

---

## 6. Bridge deck and railing variety

**Current:** All bridges are flat box decks with identical railings and gray piers.

**Suggestions:**
- Hash the bridge feature to choose a deck style:
  - **Flat slab** — current default
  - **Arched** — box with a half-cylinder (`sphereGeometry` half) on top, or just a thicker center box tapering to edges
  - **Truss** — add vertical and diagonal box members between deck and a top rail for major bridges (`major === true`), making the bridge read as steel from a distance
- Railing material: vary between `#7c8179` (current) and `#5c5f56` (darker metal) based on bridge hash.
- Pier caps: add a small box or cylinder at the top of each pier to simulate a bearing seat.

---

## 7. Water edge details

**Current:** Water is a flat fill with a single `waterColor`.

**Suggestions:**
- Along the coastline (`water` polygon edges), place low-profile dock meshes (thin elongated boxes, `scale(length, 0.08, 1.5)`) where the shoreline is straight and > 20m. Capped at 100.
- Add small boat meshes (box hull + cone cabin) in marinas/harbors, identified by `man_made === "pier"` or `landuse === "harbor"` in the vector tiles. Capped at 20.
- All water details use `c.waterColor` with lightness offset for cohesion.

---

## 8. Seasonal / weather presets

**Current:** Only time-of-day (`hour`) changes lighting and color temperature.

**Suggestions:**
- Add a `season` config field (`"summer" | "autumn" | "winter" | "spring"`). This is a pure data + shader-color change:
  - **Summer:** current defaults (green canopies, warm ground)
  - **Autumn:** shift canopy hue toward orange-red (`0.08–0.12`), increase trunk roughness to simulate bare branches mixed with leaves, ground cover turns `#c7b796`
  - **Winter:** reduce tree density by 40%, replace dropped trees with snow patches (white flat boxes), increase ground lightness by 0.15, add `#e8e8e8` snow caps on bridge decks and piers
  - **Spring:** canopy hue shifts to lime (`0.18–0.22`), add scattered flower dots (tiny spheres, pink/yellow, very low density)
- Seasonal changes are deterministic (seeded by config seed + feature hash), so the same world at different seasons feels familiar, not random.

---

## 9. Pedestrian scale figures

**Current:** No human-scale reference; the scene reads as a model, not a lived-in place.

**Suggestions:**
- On `highway` features with `class === "footway"` or `"pedestrian"`, place tiny capsule-like figures (cylinder body + sphere head, total height 1.7m) at very low density (1 per ~50m of path).
- Capped at `QUALITY.trees * 0.05` (e.g. 90 at High quality).
- Color: desaturated palette mid-tones, slightly varied per figure.
- Figures are instanced in their own mesh so they don't bloat the tree/bench count.

---

## 10. Procedural road markings

**Current:** Roads are flat colored lines with one dashed centerline for major roads.

**Suggestions:**
- Add `line-dasharray` variety in `style.ts`:
  - Motorways/trunks: solid edge + dashed center (current)
  - Primary/secondary: solid edge, no center dashes
  - Residential: no dashes, slightly lighter asphalt tone
- Edge lines: render as a second `line` layer with `line-width` 0.3–0.5 and white color at 0.4 opacity, placed just inside the road edge using `line-offset`. This adds visual complexity without extra 3D geometry.

---

## 11. Instanced mesh batching optimization (enables more variety)

**Current:** Each `kind` creates a separate `InstancedMesh`. Tree canopies, trunks, seats, legs, bins, boxes, and cylinders are already batched, but every config change rebuilds all matrices in a single `useLayoutEffect`.

**Suggestions:**
- Split large instance groups by material tint (e.g. tree canopies into 2–3 `InstancedMesh` buckets by hue band). This lets you use different `meshStandardMaterial` roughness/metalness per species without per-instance material changes.
- Use `InstancedMesh.count` to hide unused slots instead of creating/destroying meshes when counts change.
- These changes make it cheaper to double the number of detail types without hurting frame time.

---

## 12. Shadow and contact shadow variety

**Current:** One directional light with uniform shadow bias. No contact shadows.

**Suggestions:**
- Add a second, dimmer directional light from the opposite hemisphere with a smaller shadow map to soften harsh single-shadow scenes at low sun angles.
- For benches and lampposts, enable `contactShadows` via a transparent plane below each group (expensive — only enable at High quality).
- Alternatively, bake a simple radial gradient texture and project it under each instance group using a decal-like plane with `depthWrite: false`. This is cheaper than true contact shadows and adds grounding.

---

## 13. Wind / ambient motion

**Current:** All geometry is static after the collection pass.

**Suggestions:**
- Add a uniform `wind` strength parameter driven by `config.hour` (higher in afternoon) and a per-feature phase from `seeded(hash + 999)`.
- In the vertex shader (via `onBeforeCompile` on the canopy material), displace `position.y` by `sin(time * wind + phase) * amplitude`. Amplitude is highest for canopies, zero for trunks and structures.
- This costs zero JS per frame after the initial setup and makes the world feel alive.

---

## 14. Procedural river / stream banks

**Current:** Streams are flat lines with no volume.

**Suggestions:**
- Where `waterway` lines are classified as `river` or `stream` and width > 3m, add a second flat box slightly below the water surface (`y = -0.05`) in a darker sand/stone color to simulate a bank.
- For wider rivers (> 15m), add two parallel bank boxes offset laterally.
- These are cheap instanced boxes derived from existing `streams` layer geometry.

---

## 15. Facade depth / recess effect

**Current:** Facade panes are flat boxes coplanar with the building extrusion face.

**Suggestions:**
- Push pane positions inward by `0.08` along the outward normal (already computed for z-fighting). Add a second thin box behind each pane in a darker shade (`groundColor` or a mid-tone) to simulate a recessed window reveal.
- This doubles the facade part count, so gate it behind `quality !== "eco"` or halve the per-building budget when enabled.

|---|---|---|---|
| **High** | Tree species variety (shapes + hue families) | Immediate visual richness | Low |
| **High** | Expanded facade tones + window shapes | Buildings feel less repetitive | Low |

| **Low** | Procedural river banks | Visual consistency | Low |

## Data flow summary

All new detail types should plug into the existing event-driven pipeline:

```
tile load / camera stop (debounced 250ms)
  → collectDetails(map, config)
    → collectStructures (facades, rooftops, bridges)
    → queryRenderedFeatures for parks, landcover, water, roads, waterways, highway
    → new collectors (ground cover, lampposts, docks, figures)
  → setData(WorldDetails)
    → Details.tsx renders InstancedMesh per kind
```

Keep the hard caps (`QUALITY.trees`, bridge 500-part limit, etc.) and add per-kind caps so adding variety never breaks performance budgets.
